## 0. 문서 사용 원칙

- 이 문서는 **제품 의도와 결정사항의 기준 문서**다.
- 다이어그램 I-1~I-8은 이 문서를 시각화한 보조 자료다.
- 이미지 생성 과정에서 결정 ID나 예시 숫자가 일부 어긋날 수 있으므로, **결정 ID와 정책 의미는 이 문서를 우선**한다.
- 실제 테이블명, 필드명, 모듈명, 마이그레이션 방식은 현재 코드 조사 후 기술설계 단계에서 정한다.
- `[확정]`은 구현에서 임의 변경하지 않는다.
- `[임시]`은 v1 운영값이며 이유를 함께 보존하고 실제 데이터 검증 후 조정할 수 있다.
- `[현재 제외]`는 이번 Growth vNext 구현 범위에 포함하지 않는다.
- 애매한 사항을 Cursor가 임의로 채우지 않는다. 제품 의미가 달라지는 경우 먼저 질문한다.

# 1. 제품 목적

Growth vNext는 단순한 데이터 요약 화면이 아니다.

운영 데이터에서 일반 코드가 검증 가능한 사실과 수치를 계산하고, 각 분석의 데이터 충분성과 중요도를 판정한 뒤, LLM은 이 근거들을 연결해 교사가 이해할 수 있는 하나의 이야기로 설명한다.

최종 Growth는 최소한 다음 질문에 답할 수 있어야 한다.

1. 최근 이 아동에게 어떤 변화가 있었는가?
2. 학습·진도·또래·포인트·독서에서 서로 연결되는 흐름은 무엇인가?
3. 서로 다른 방향을 보이는 데이터가 있는가?
4. 교사가 지금 현실적으로 무엇을 해볼 수 있는가?
5. 다음 분석에서 무엇을 다시 확인하면 되는가?

# 2. 절대 원칙 — INV

## INV-001 [확정]
숫자, 비율, 차이, 중앙값, 완료예상에 필요한 산술은 일반 코드가 계산한다.  
LLM은 계산된 사실을 선택적으로 연결하고 해석한다.

## INV-002 [확정]
없는 날짜, 페이지, 학습 여부, 행동을 추정해 사실로 채우지 않는다.

## INV-003 [확정]
출석과 학습 수행을 동일시하지 않는다.

## INV-004 [확정]
또래 진도 비교는 동일한 비교 기준일(`as_of`)을 사용한다.  
각 아동의 서로 다른 최신 기록 날짜를 직접 비교하지 않는다.

## INV-005 [확정]
`verified`는 교사가 실제 교재를 직접 보고 학습 결과나 범위를 확인한 경우에만 사용한다.

## INV-006 [확정]
현재 센터의 특정 과목 구성이나 100/200 포인트 정책을 제품 공통 규칙으로 하드코딩하지 않는다.

## INV-007 [확정]
센터의 자연어 정책은 **해석 배경**이지 특정 아동에게 관측된 사실이 아니다.

## INV-008 [확정]
독서기록 원문 분석에서는 독서 전용 AI가 실제 최종 제출 원문을 직접 읽을 수 있어야 한다.

## INV-009 [확정]
Growth는 “무슨 일이 있었는가”에서 끝나지 않고, 데이터에 근거한 현실적인 다음 행동을 제안한다.

## INV-010 [확정]
교사가 제안을 실제로 실행했는지 추적하고 이후 결과와 연결하는 폐쇄루프는 현재 범위에서 제외한다.

## INV-011 [확정]
학습 수행률, 진도, 포인트, 또래 차이를 아동의 학습 의지·성실성·집중력·학업 능력 등 개인 특성의 직접 증거로 해석하지 않는다.

## INV-012 [확정]
센터 자유서술 정책은 아동 사실의 계산·포함·제외 여부를 결정하지 않는다.  
어떤 지표를 계산하고 어떤 사실을 AI에 제공할지는 구조화된 센터 설정과 일반 코드가 결정한다.  
자연어 정책은 검증된 사실이 만들어진 이후 LLM 해석 배경으로만 사용한다.

# 3. 학습 입력·정상학습일·사후입력

## LEARN-001 [확정]
정상학습일 대비 실제 공부가 확인된 날의 비율을 `학습 수행률`로 사용한다.

## LEARN-002 [확정]
일일 학습 범위는 `시작 페이지 + 끝 페이지`를 저장한다.

## LEARN-003 [확정]
학습 상태와 기록 검증 상태는 서로 다른 축이다.

- 학습 상태: `studied / explicit_not_studied / unknown`
- 기록 검증 상태: `observed / verified`

`observed`는 시스템에 기록되었으나 교사가 실제 교재를 확인하지 않은 상태다.  
`verified`는 교사가 실제 교재를 직접 확인한 상태다.

## LEARN-004 [임시]
기간 변화의 주요 분석은 비교하는 양쪽 기간 모두 정상학습일이 최소 8일 이상일 때 허용한다.

이유: 너무 짧은 기간의 비율 급변을 주요 변화처럼 과장하지 않기 위해.

## LEARN-005 [임시]
`데이터 확인률 = (studied + explicit_not_studied) / 정상학습일`

- 70% 이상: 주요 분석 가능
- 50% 이상 70% 미만: 제한적 분석
- 50% 미만: 기간 변화 해석 금지

이유: unknown 날짜가 결론을 지배하는 것을 방지하기 위해.

## LEARN-006 [임시]
기간 비율 차이가 10%p 미만이면 숫자는 표시할 수 있으나 “큰 변화”로 주요 insight에 올리지 않는다.

이유: 작은 변화를 LLM이 과장하는 것을 방지하기 위해.

## LEARN-012 [확정]
정상학습일은 “센터가 문을 연 날” 자체가 아니라, 해당 아동에게 해당 과목의 학습이 예정된 날을 의미한다.

## LEARN-013 [확정]
센터는 과목별 예정 학습요일을 설정할 수 있어야 한다.

## LEARN-014 [확정]
법정공휴일 및 센터가 지정한 비학습일은 정상학습일 분모에서 제외한다.  
미학습이나 unknown으로 계산하지 않는다.

## LEARN-015 [확정]
법정공휴일은 시스템 기본값으로 제공할 수 있고, 센터 행사·체험·휴무 등은 관리자가 월별로 추가/수정할 수 있어야 한다.

## LEARN-016 [확정]
정상학습일에 기록이 없다는 이유만으로 미학습으로 판정하지 않는다.  
명시적 미학습 입력이 없으면 `unknown`이다.

## LEARN-017 [확정]
빠진 학습기록의 사후입력 대상 판단은 포인트 기록 존재 여부와 독립적이다.

## LEARN-018 [확정]
사후입력 화면은 해당 날짜에 기대된 과목들을 한 화면에서 처리한다.

각 과목은 최소 다음 선택을 지원한다.

- 공부함 → 시작/끝 페이지 입력
- 공부하지 않음
- 기억 안 남

## 입력 변경 이력 [확정]
수정과 삭제는 변경 이력에 남긴다.  
삭제는 예외적 상황에서만 허용하고 일반적으로 수정이 우선이다.

# 4. 진도·고유페이지·완료예상

## LEARN-019 [확정]
교재 진도는 기록된 시작~끝 페이지들의 합집합인 **고유 풀이페이지(unique coverage)**로 계산한다.

예: `70~71 → 80~81 → 72~73`이면 70~81 전체를 풀었다고 추정하지 않는다.

## LEARN-020 [확정]
진도율 분모는 전체 물리 페이지가 아니라 **실제 배정 학습페이지**를 사용한다.

- 일시적으로 건너뛴 페이지: 분모에 남김
- 교사 계획상 영구 제외된 페이지: 분모에서 제외

## LEARN-021 [확정]
현재 센터의 과거 상세 복원은 2학기 교재만 대상으로 한다.  
복원 과정에서도 건너뛴 페이지를 자동 추정하지 않는다.

## LEARN-022 [확정]
교재 시작부터 coverage 이력이 신뢰 가능한 경우에만 전체 교재 진행률을 정확한 값으로 사용한다.

시스템 도입 당시 이미 중간 진도였고 과거 풀이범위를 모르는 교재는 과거 페이지를 완료로 추정하지 않는다.

## LEARN-023 [임시]
완료예상은 **같은 교재의 가장 최근 유효 학습 세션이 최소 8개** 있을 때 제공하는 것을 v1 기본값으로 한다.

- v1에서는 별도의 `최근 2~4주 설정 가능 window`를 두지 않는다.
- v1에서는 `최근 4주 중 공부한 날 3일 미만이면 N/A` 같은 별도 일수 기준을 사용하지 않는다.
- 완료예상용 pace는 같은 교재의 가장 최근 유효 세션 8개를 기준으로 계산한다.

이유: 몇 번의 학습량만으로 장기 완료시점을 과도하게 예측하지 않으면서, 일수/기간 기준을 여러 개 겹쳐 복잡하게 만들지 않기 위해.

## LEARN-024 [확정]
완료예상에서 대표적인 세션당 신규 진행량은 평균보다 중앙값 기반 계산을 우선한다.

## LEARN-025 [확정]
교재 완료예상은 단일 날짜가 아니라 기간 범위로 제공한다.  
표현에는 “최근 학습 흐름이 유지될 경우” 같은 조건을 명시한다.

## LEARN-026 [임시]
목표 완료일과 예상 완료 범위를 비교한다.

- 예상 범위가 목표일과 겹침: 주요 경고 없음
- 소폭 지연: 상세정보 표시 가능, 주요 insight 아님
- 예상 범위의 빠른 쪽조차 목표일보다 약 2주 이상 늦음: 주요 insight 후보
- 목표 완료일이 지났고 미완료: 주요 insight 후보

이유: 며칠 단위 예측오차는 과장하지 않으면서 실제 1~2개월 지연 가능성은 미리 확인하기 위해.

## LEARN-033 [확정]
학습 빈도와 교재 진도는 서로 다른 지표다.

진도는 학습 횟수가 아니라 `고유 풀이페이지 / 실제 배정 학습페이지`로 계산한다.  
학습 빈도가 높다는 이유만으로 진도가 빠르다고 해석하지 않는다.

# 5. 또래 비교

## 기본 비교 경계 [확정]
센터 간 아동 데이터를 섞지 않는다.  
또래 비교는 **동일 센터 내부**에서만 수행한다.

## LEARN-027 [확정]
진도 또래비교는 동일한 `as_of` 기준일을 사용한다.

## LEARN-028 [확정]
진도 또래비교의 기본값은 동일 교재의 고유 풀이범위 비율이다.  
최고 도달 페이지는 주요 비교지표로 사용하지 않는다.

## LEARN-029 [확정]
전체 coverage 이력이 신뢰 가능하지 않은 교재는 전체 진행률을 추정해서 또래비교하지 않는다.  
필요하면 도입 이후 관측된 범위만 제한적으로 사용할 수 있다.

## LEARN-030 [임시]
또래 비교에 포함되는 아동도 비교기간의 데이터 확인률을 적용한다.

- 70% 이상: 정상 비교 대상
- 50~70%: 제한적
- 50% 미만: 주요 비교집단에서 제외

이유: 기록 누락으로 실제보다 낮게 보이는 편향을 줄이기 위해.

## LEARN-040 [확정]
또래 집단의 대표값은 기본적으로 중앙값을 사용한다.

> ID 정리: I-3 v2.2 이미지에서 `LEARN-031`이 완료예상 관련 다른 의미로 잘못 사용되어 충돌이 발생했으므로, 또래 중앙값 원칙의 정식 ID를 `LEARN-040`으로 재부여한다.

## LEARN-034 [임시]
본인 제외 비교 가능한 다른 아동 수:

- 3명 이상: 정상 또래 비교 가능
- 2명: 참고 비교
- 0~1명: 비교 제공 안 함

이유: 지역아동센터의 실제 학년별 인원이 작아 5명 기준에서는 대부분 기능이 작동하지 않을 가능성이 높기 때문.

## LEARN-036 [확정]
통계적 이상치 제거를 하지 않는다.  
페이지 범위 오류 등 객관적으로 유효하지 않은 데이터만 제외한다.

## LEARN-037 [확정]
v1 또래비교에서는 순위, 백분위, 상위/중위/하위 분류를 제공하지 않는다.

## LEARN-038 [확정]
v1 또래비교 기본 지표는 다음 3개다.

1. 동일 교재 고유 풀이범위 비율(진도율)
2. 학습 수행률
3. 분석기간 총 포인트

공부한 날 수와 세션 수는 기본 또래비교 지표로 사용하지 않는다.

포인트 비교는 같은 센터·동학년의 동일한 운영정책 맥락에서 **기록된 보상/참여/학습 결과의 차이를 참고하는 보조 신호**이며, 아동의 성실성·의지·능력으로 확대해석하지 않는다.

## LEARN-039 [확정]
비교 가능한 다른 아동이 2명뿐인 경우 정확한 비교값은 `근거 보기`에서 참고용으로만 제공한다.

- 핵심 insight 사용 금지
- 행동 제안의 단독 근거 사용 금지
- 상대적 우열 표현 금지

0~1명은 또래 통계를 생성·표시하지 않는다.

## 또래 차이 중요도 [임시]
진도 coverage 차이:

- 5%p 미만: 참고
- 5~10%p: 보조 후보
- 10%p 이상: 주요 후보

이유: 작은 또래 차이를 LLM이 중요한 격차로 과장하는 것을 방지하기 위해.

# 6. 포인트

## POINT-001 [확정]
Growth vNext에서는 수동포인트의 정규화 카테고리뿐 아니라, 분석에 의미가 있는 항목명 및 자유서술 이유도 보조 맥락으로 제공할 수 있다.

단, 자유서술 자체를 아동의 능력·성격·동기 사실로 취급하지 않는다.

## POINT-002 [확정]
수동포인트 `reason`은 선택적 보조정보다.  
reason이 없는 것이 정상적인 상태일 수 있으며, 어떤 핵심 Growth 분석도 reason 존재에 의존하지 않는다.

## 현재 기반 [기구현]
포인트 구성(Composition), 의미 카테고리 정규화, 센터 자연어 정책 연결은 기존 Growth Evidence v2 기반을 최대한 재사용한다.

# 7. 독서 전용 AI 서비스

## READ-003 [확정]
독서 원문 분석은 전체 Growth AI와 논리적으로 분리된 독서 전용 AI 단계로 둔다.

독서 분석 모델과 전체 Growth 모델은 서로 다를 수 있다.

## READ-005 [임시]
원문 변화 비교는 최근 최대 8개 vs 직전 최대 8개를 사용한다.

각 기간별 기록 수:

- 5~8개: 주요 변화 분석 가능
- 3~4개: 제한적 분석
- 0~2개: 기간 변화 결론 금지

이유: 반복되는 문장 패턴을 볼 수 있는 표본을 확보하면서 원문 입력량·비용·최근 변화 희석을 제한하기 위한 v1 균형값.

## READ-006 [확정]
AI가 보는 디지털 독서기록은 교사 검토 후의 최종 제출 기록이다.

따라서 결과는 “제출된 기록에서 관찰되는 표현·내용 변화”로 기술하며, 독립적인 글쓰기 능력·사고력·공감능력·성격·정서·인지능력 평가로 확대하지 않는다.

## READ-007 [확정]
기록 수, 글자 수, 문장 수, 완독 수, 완독 기간 등 명확한 양적 통계는 일반 코드가 계산한다.  
독서 AI는 실제 원문을 읽고 의미·문장·내용 패턴 변화를 해석한다.

## READ-008 [확정]
독서 AI는 DB에 저장된 최종 제출 원문을 직접 읽는다.

별도의 맞춤법 교정, 문장 재작성, 요약, 키워드 특성화, 연락정보 탐지기 같은 사전 전처리 시스템을 v1에서 만들지 않는다.

AWS Guardrail은 별도의 안전 경계로 사용한다.

## READ-009 [확정]
동일한 독서 분석 입력에 대한 정상 결과는 캐시하여 재사용한다.

## READ-010 [확정]
독서 분석 기능은 전체 Growth에 종속시키지 않고 재사용 가능한 서비스 경계로 설계한다.

현재 주요 사용처:
- 전체 Growth

향후 사용 가능:
- 독서 상세 분석 화면
- 교사용 챗봇
- 기타 독서 기능

특정 MCP/A2A 프로토콜 사용을 요구하지 않는다.

## READ-011 [현재 제외]
독서 원문 기반 위기·심리·민감내용 탐지 시스템은 현재 Growth vNext 범위에 포함하지 않는다.

## READ-013 [확정]
독서 캐시 fingerprint는 단순 기록 ID가 아니라 독서 AI가 실제로 받는 분석 입력과 분석 버전을 기반으로 생성한다.

포함 대상:
- 최근/직전 선택 기록의 실제 원문 및 필요한 메타데이터
- 코드 계산 정량값
- 비교 window 설정
- prompt/analyzer/model version

새 기록 추가 또는 기존 기록 수정으로 입력 window가 달라지면 새 fingerprint가 생성된다.

데이터 변경 즉시 분석하지 않고 Growth/독서상세/챗봇 등에서 필요할 때 lazy하게 생성한다.

# 8. 전체 Growth AI

## AI-001 [확정]
전체 Growth AI는 학습·진도·또래·포인트·독서·센터정책 등 여러 분석결과를 연결해 종합한다.

## AI-002 [확정]
최종 리포트에는 핵심 변화뿐 아니라 `지금 해볼 것`과 `다음에 확인할 것`을 포함한다.

## AI-003 [확정]
행동 제안은 1~3개로 제한하고 센터에서 현실적으로 실행 가능한 작은 조치만 허용한다.

## AI-004 [확정]
제안 실행 여부 추적은 하지 않는다.

## AI-005 [확정]
전체 Growth AI 앞에서 일반 코드가 각 분석을 사전 분류한다.

- `major`: 주요 후보
- `supporting`: 보조
- `reference`: 참고
- `unavailable`: 사용 불가

## AI-006 [확정]
서로 관련된 분석 노드는 가능한 한 하나의 종합 해석으로 연결한다.  
같은 현상을 숫자별로 반복 나열하지 않는다.

## AI-007 [확정]
서로 다른 노드가 다른 방향을 보이면 억지로 하나의 긍정/부정 결론으로 통합하지 않는다.  
“서로 다른 흐름이 관찰된다”고 표현할 수 있어야 한다.

## AI-008 [확정]
여러 노드의 동시 발생은 연결해서 설명할 수 있으나, 한 노드가 다른 노드의 원인이라고 단정하지 않는다.

## AI-009 [확정]
핵심 변화 개수를 강제로 채우지 않는다.

- 0~4개
- 의미 있는 주요 후보가 없으면 `뚜렷한 주요 변화 없음` 허용

## AI-010 [확정]
동일 현상의 중복 insight는 합친다.  
분야 다양성을 위해 의미 없는 항목을 억지로 추가하지 않는다.

## AI-011 [확정]
모든 행동 제안은 최소 하나 이상의 실제 분석 근거와 연결되어야 한다.  
근거와 직접 연결되지 않는 일반적인 교육 조언은 생성하지 않는다.

## AI-012 [확정]
`다음에 확인할 것`은 1~3개를 제공한다.  
이는 추적 시스템이 아니라 다음 Growth에서 볼 지표를 안내하는 문구다.

## AI-013 [확정]
전체 Growth AI는 독서 전용 AI가 제공한 관찰 범위를 넘어 아동의 글쓰기·인지·정서 능력으로 확대해석하지 않는다.

## AI-014 [확정]
전체 Growth AI와 독서 전용 AI의 역할 및 입출력 계약은 특정 모델에 종속시키지 않는다.  
모델은 성능·비용 검증 후 교체 가능해야 한다.

## AI-015 [확정]
AI 앞의 코드 선별기는 분석 결과를 자연어로 재해석하지 않는다.  
데이터 충분성 및 사전에 정의된 수치 기준만 적용해 주요/보조/참고/사용불가 태그를 붙인다.

## AI-016 [현재 제외]
교사의 Growth 결과 유용성/품질 피드백 저장 기능은 현재 구현하지 않는다.  
향후 멀티센터 운영 시 운영 품질지표로 재검토한다.

## AI-018 [확정]
능력·의지·성실성·집중력·인과관계 등의 금지 해석은 Growth AI 시스템 프롬프트의 강제 도메인 규칙으로 적용한다.

현재 factual validator는 숫자·단위·근거·형식의 사실 일관성을 검증한다.  
자연어 의미 전체를 판정하는 별도의 semantic policy validator / classifier는 v1에서 만들지 않는다.

실운영 데이터가 쌓인 뒤 위반이 의미 있게 발생하면 별도 classifier 등을 재검토한다.

## AI-019 [확정]
전체 Growth AI 호출은 현재 약 20초 backend timeout을 기본으로 한다.

timeout 시:
- 숨은 LLM 재시도 없음
- 결과 미노출
- 사용자에게 `[다시 분석]` 제공

## 전체 Growth 캐시 [현재 제외]
v1에서는 전체 Growth 생성결과를 별도로 캐시하지 않는다.  
현실적으로 데이터가 자주 바뀌고, 현재 규모에서 추가 복잡성을 만들 이유가 작다.

# 9. 센터 정책과 AI 근거 묶음

## 순서 [확정]

1. 구조화된 센터 설정을 일반 코드 계산에 적용
2. 검증된 아동 사실 생성
3. 데이터 충분성 및 중요도 태깅
4. AI에 허용된 사실만 근거 묶음으로 구성
5. 센터 자연어 정책을 해석 배경으로 별도 추가
6. 전체 Growth AI 실행

센터 자연어 정책이 어떤 아동 사실을 계산하거나 제거할지 결정하지 않는다.

## 현재 Evidence 기반
기존 `growth_teacher_evidence_v2`, `growth_teacher_factual_validator_v3`, `growth_teacher_prompt_v9` 및 기존 센터 정책 연결 작업을 가능한 한 확장·재사용한다.

Growth vNext 구현을 이유로 현재 Evidence 구조를 근거 없이 전면 교체하지 않는다.

# 10. 사실검증·안전·실패 처리

## SAFE-001 [확정]
독서 입력 안전검사에서 일부 기록을 사용할 수 없는 경우, 가능한 범위에서 해당 독서 원문 분석만 제한하고 나머지 일반 Growth 계산은 계속한다.

구체적인 Guardrail 호출 단위는 현재 코드/실제 API 동작을 확인한 뒤 기술설계에서 정한다.

## SAFE-002 [확정]
독서 AI 호출 실패 시 숨은 LLM 재시도를 하지 않는다.

- 동일 입력에 대한 정상 캐시가 있으면 사용 가능
- 없으면 독서 원문 분석만 unavailable
- 독서 정량통계와 전체 Growth의 다른 영역은 계속 사용 가능

## SAFE-003 [확정]
전체 Growth AI 생성 실패 시 숨은 재시도를 하지 않는다.  
일반 코드 기반 Growth는 유지하고 AI 영역에 실패 상태와 `[다시 분석]`을 제공한다.

## SAFE-004 [확정]
사실검증 실패 결과는 사용자에게 노출하지 않는다.  
자동 재생성하지 않고 `[다시 분석]`을 제공한다.

## 전체 Growth 실패 종류
최소 다음 실패는 구분되어야 한다.

- LLM timeout
- LLM/API 오류
- 구조화 출력/JSON 형식 오류
- factual validator 실패
- AWS Guardrail 출력 실패
- DB 저장 실패

실패가 발생해도 가능한 deterministic Growth 영역은 계속 표시한다.

# 11. 리포트 스냅샷·사후 변경

## REPORT-001 [확정]
Growth 리포트는 생성 당시 사용한 계산 결과와 근거를 스냅샷으로 보존한다.

포함 예:
- 본인 계산값
- 당시 또래 중앙값
- 당시 비교인원
- 비교 기준일
- 당시 차이값
- 사용한 근거 ID/값

이후 원본 데이터가 수정되어도 과거 리포트의 숫자와 근거를 조용히 변경하지 않는다.

다른 아동의 사후수정 때문에 기존 리포트를 stale 처리하거나 자동 재계산하지 않는다.

새 Growth 분석을 요청할 때만 현재 최신 데이터로 다시 계산한다.

## REPORT-002 [확정 / 구현 방식 미정]
과거 Growth 리포트는 **해당 리포트 대상 아동 자신의 분석 관련 원본 데이터가 생성 이후 변경되었는지** 판별할 수 있어야 한다.

변경된 경우:
- 기존 리포트는 그대로 표시
- `이 분석 이후 아동의 기록이 변경되었습니다.` 안내
- `[다시 분석]` 제공

구현 방식은 현재 코드 조사 후 결정한다.

후보:
- revision counter
- dirty flag
- input fingerprint

# 14-1. 다이어그램 ID/정책 정합성 정리

Cursor에 넘길 때 **이 계약서 v0.2를 최우선 기준**으로 사용한다.

특히 I-3 v2.2 이미지에는 이미지 정리 과정에서 합의되지 않은 다음 내용이 들어갔다.

- `LEARN-031 = 최근 4주 기준 공부한 날이 3일 미만이면 완료예상 N/A`
- `LEARN-032 = 최근 pace window 기본 4주, 2~4주 설정 가능`

위 두 항목은 **Growth vNext v1의 정식 정책이 아니다.**

v1의 정식 완료예상 기준은 `LEARN-023`이다.

- 같은 교재의 가장 최근 유효 학습 세션 최소 8개
- 별도 2~4주 configurable window 없음
- 별도 3일 threshold 없음

또래 대표값 중앙값 원칙은 ID 충돌 제거를 위해 `LEARN-040`으로 재부여했다.

# 15. 현재 코드와의 관계

현재 브랜치의 기존 기능을 최대한 재사용한다.

이미 존재하는 기반 예:
- deterministic Growth
- Growth Evidence Packet v2
- center policy 자연어 연결
- Point Composition / semantic normalization
- Growth AI runtime
- factual validator v3
- AWS Guardrail
- Growth UI
- reading 관련 기존 데이터/화면
- 아동 식별/QR 관련 기존 기능

Growth vNext 구현 전에 반드시 현재 코드를 조사하여 다음을 분리한다.

1. 그대로 재사용 가능한 것
2. 확장해야 하는 것
3. 새로 필요한 것
4. 레거시와 충돌하는 것
5. 마이그레이션이 필요한 것

---

# 16. 구현 전 Cursor 조사 산출물

Cursor의 첫 Growth vNext 작업은 **코드 구현이 아니라 조사와 기술설계**다.

반드시 다음 5가지를 제출한다.

1. 현재 코드에서 재사용 가능한 기존 기능
2. 본 계약과 현재 코드 사이의 gap
3. 필요한 DB 변경 및 마이그레이션 후보
4. 모듈/데이터 흐름 기술설계
5. 단계별 구현 순서와 테스트 계획

이 단계에서는:
- 코드 수정 금지
- migration 생성 금지
- commit 금지
- push 금지

제품 의미가 애매하면 임의 결정하지 말고 질문한다.

# 17. 구현 기본 순서

기술설계 검토 후 작은 단위로 진행한다.

1. DB/도메인 모델
2. 학습 입력·사후입력
3. 정상학습일·학습 수행 계산
4. 고유페이지·진도·완료예상
5. 또래비교
6. 독서 입력/독서 분석 서비스
7. Evidence / 전체 Growth 연결
8. UI 확장
9. 통합 테스트
10. staging 검증

각 단계는 `구현 → 테스트 → 보고 → 검토 → 다음 단계` 순서로 진행한다.
